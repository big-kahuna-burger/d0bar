Four shapes, because one shape proves nothing

      

        Each button emits a genuinely distributed trace: the page's own SDK produces the client
        spans, and the fixture server answers with the server side — a SERVER span
        parented to the browser's span, and the database, cache, queue and downstream-service
        work beneath it. Three or four services per trace, five levels deep.
      

      

        

          Button
          Shape
          What it is for
        

        

          Checkout
          Deep, with a parallel fan-out
          
            Three pricing calls start together, so bars overlap rather than forming a staircase.
            The card charge 503s and the retry succeeds — a span erroring beside a sibling that
            did not.
          
        

        

          Search fan-out
          Wide: eight siblings at once
          
            Depth tells you nothing here and only durations do. One shard is five times slower
            than the rest, which is the thing you actually opened the panel to find.
          
        

        

          Failure cascade
          An error propagating up three levels
          
            The leaf 500s and every ancestor is marked ERROR on the way back up,
            three services from the click. The trace you open after seeing one red row.
          
        

        

          Cold start
          Eleven serial spans
          
            Nothing overlaps, the total is the sum, and the only question is which link to
            break. The shape where a waterfall earns its keep.
          
        

      

      

        The server side is synthesised around real timings and labelled as such
        (telemetry.sdk.name: d0bar-fixture). The trace context, the route, the
        status and every timestamp are real; there is no Postgres behind it and nothing is
        charged. It is also gated on a header only these buttons send — the measured arms fetch
        the same routes, and a fixture that did work behind a request whose timing is the
        subject would be measuring itself.
      

      
Why some rows say NONE, and why that is right

      

        d0bar reads trace context; it never adds any. The worker parses
        traceparent off each request and nothing more — injecting a header would be
        the toolbar modifying the traffic it reports on. So a row shows a trace id only if the
        application put one there.
      

      

        The scenario buttons set traceparent from their active spans. Other page
        requests may remain untraced, which is why the panel can still show
        NONE rows.

What you will see, and what you will not

      

        

          Tier
          On a real page
        

        

          1 — requests, vitals
          
            Full. Read from the browser's own entries, so third-party traffic shows up too.
          
        

        

          2 — service worker
          
            Off, and the panel says so. A service worker script must be
            same-origin as the page it controls, so one served from this dev server cannot be
            registered onto someone else's site — no configuration changes that. Requests read
            as untraced. This is the degraded path working correctly, not a failure. To see tier
            2 live, use this page, or serve d0bar from your own origin.
          
        

        

          4 — OpenTelemetry
          Live only if the page already runs an OTel web SDK. Most do not.
        

      


      
When it will not load at all

      
    
        
  • 
          Content-Security-Policy. Most large sites block a script from an
          origin they did not list. Nothing appears and the console says why. Try a smaller
          site, or your own app in development.
        
    • 
        
  • 
          HTTPS pages. A page on https: will not load a script
          over http:. Use this against a local or http: page.
        
    • 
        
  • 
          Server not running. This page is served by it, so if you are reading
          this it is up.
